1. WHAT IS SWAGGER UI & OPENAPI IN GIVENAIJA?
================================================================================

Imagine visiting a high-end restaurant:
- The OpenAPI Specification is the official recipe book and menu description 
  written down in precise detail (what ingredients each dish requires, what size 
  plate it is served on, and how much it costs). In software, this is a standard 
  JSON document generated automatically at `/openapi.json`.
- Swagger UI is the physical interactive menu handed to the guest at the table. 
  It lets you look at every dish, see what ingredients it expects, and even 
  press a button to "taste" the dish (send a live HTTP request to your running 
  backend and get real data back instantly).

In GiveNaija:
- We built the backend using FastAPI (Python).
- FastAPI reads our Python type hints, Pydantic schemas, and route decorators.
- From those, FastAPI automatically compiles the official OpenAPI 3.1.0 specification.
- FastAPI then serves Swagger UI right in your browser at `/docs`.
- There is ZERO manual writing of documentation. If a developer changes a field 
  in `app/domains/campaigns/schemas.py`, Swagger UI updates automatically!

2. HOW TO ACCESS SWAGGER (URLS, PORTS, AND REDIRECTIONS)
================================================================================

When you start the GiveNaija server (e.g. `uv run uvicorn app.main:app --reload` 
or via Docker Compose), the API runs on port 8000.

You can access the API documentation via any of these URLs:

1. Root Auto-Redirect:
   URL: http://127.0.0.1:8000/ or http://localhost:8000/
   What happens: `app/main.py` defines a root route that automatically issues an 
   HTTP 307 redirect directly to `/docs`. You don't even have to remember the 
   word "docs" — just opening the root URL takes you straight to Swagger!

2. Interactive Swagger UI:
   URL: http://127.0.0.1:8000/docs
   What happens: Renders the full interactive Swagger documentation where you 
   can test endpoints, log in, send requests, and inspect live responses.

3. Alternative ReDoc Documentation:
   URL: http://127.0.0.1:8000/redoc
   What happens: Renders a clean, three-panel static reading view of your API 
   documentation (great for reading and printing specifications).

4. Raw OpenAPI JSON Contract:
   URL: http://127.0.0.1:8000/openapi.json
   What happens: Outputs the machine-readable OpenAPI 3.1 JSON document that 
   powers Swagger, frontend SDK generators, and API gateways.

GiveNaija uses stateless JSON Web Tokens (JWT) for authentication. Every secure

A. Pre-Seeded Demo Accounts (From seed.py)
--------------------------------------------------------------------------------
When you seed the database (`uv run python seed.py`), three accounts are created:

1. ADMIN ACCOUNT (Role: admin)
   Email:    admin@givenaija.org
   Password: Admin123!
   Power:    Can create/close campaigns, reconcile ledgers, inspect audit logs.

2. FINANCE OFFICER ACCOUNT (Role: finance)
   Email:    finance@givenaija.org
   Password: Finance123!
   Power:    Can record confirmed bank donations, view ledger, export statements.

3. DONOR ACCOUNT (Role: donor)
   Email:    donor@example.com
   Password: Donor123!
   Power:    Can submit pledges, view personal donations, download receipts.

--------------------------------------------------------------------------------
B. How to Authenticate in Swagger Step-by-Step
--------------------------------------------------------------------------------
Follow these 4 simple steps to unlock protected endpoints in Swagger:

Step 1: Get Your Token via /auth/login
   1. Expand the "Authentication" tag in Swagger.
   2. Click on `POST /api/v1/auth/login`.
   3. Click the white "Try it out" button on the right.
   4. In the Request body box, fill in the credentials (for example, Admin):
      {
        "email": "admin@givenaija.org",
        "password": "Admin123!"
      }
   5. Click the blue "Execute" button.
   6. Look at the Server response (HTTP 200). You will see:
      {
        "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
        "token_type": "bearer",
        "user": { ... }
      }
   7. Highlight and copy ONLY the token text inside the quotation marks 
      (the string starting with "ey...").

Step 2: Open the Authorize Modal
   1. Scroll up to the top right of the Swagger page.
   2. Click the green "Authorize" button (with the open padlock icon).

Step 3: Paste and Authorize
   1. In the "Value" text field under `HTTPBearer (http, Bearer)`, paste the 
      token you copied.
      Note: You can paste just the raw token string (e.g. `eyJ...`). Swagger UI 
      automatically prefixes it with `Bearer `.
   2. Click the "Authorize" button inside the modal, then click "Close".

Step 4: Verify Authorization
   - Notice that the padlock icon on the green button is now LOCKED!
   - Every endpoint with a lock icon next to its name will now automatically 
     include your Bearer token in its HTTP request header!

--------------------------------------------------------------------------------
C. Role-Based Access Control (RBAC): 401 vs 403 in Swagger
--------------------------------------------------------------------------------
GiveNaija strictly enforces two levels of security:
- HTTP 401 UNAUTHORIZED:
  Triggered when you try to call a locked endpoint without clicking Authorize, 
  or if your token has expired.
  Message: "Authentication required. Missing Bearer token."
- HTTP 403 FORBIDDEN:
  Triggered when you ARE logged in, but your role does not have permission.
  For example, if you log in as `donor@example.com` and attempt to call 
  `POST /api/v1/campaigns` (which requires `admin`), the server returns 403.
  Message: "Access forbidden. Requires one of roles: admin"

TAG 1: HEALTH
--------------------------------------------------------------------------------

1. GET /health
   - Summary: Health check endpoint for orchestrators and monitoring probes.
   - Purpose: Allows Docker, Kubernetes, AWS, or uptime monitors to verify that 
     the FastAPI server is alive and responding.
   - Permission: Public (No login needed).
   - Parameters: None.
   - How to test in Swagger:

   - Expected Response (HTTP 200 OK):
     {
       "status": "healthy",
       "app": "GiveNaija API",
       "environment": "development"
     }

--------------------------------------------------------------------------------
TAG 2: AUTHENTICATION (/api/v1/auth)
--------------------------------------------------------------------------------

2. POST /api/v1/auth/register
   - Summary: Register a new user account.
   - Purpose: Creates a brand-new user. If the role chosen is `donor` (the default), 
     the system automatically creates an associated `Member` profile with an 
     NGO membership number.
   - Permission: Public.
   - Request Body (`RegisterRequest`):
     {
       "email": "newdonor@example.com",
       "password": "SecurePassword123!",
       "role": "donor",
       "phone": "+2348012345678"
     }
   - How to test in Swagger:
     Click "Try it out" -> Paste JSON -> Click "Execute".
   - Expected Response (HTTP 201 Created):
     {
       "id": 4,
       "email": "newdonor@example.com",
       "role": "donor",
       "is_active": true,
       "created_at": "2026-09-22T12:00:00Z"
     }
   - Potential Errors:
     * HTTP 400 Bad Request: If email is already registered.
     * HTTP 422 Unprocessable Entity: If password is under 8 characters or email 
       is invalid.

3. POST /api/v1/auth/login
   - Summary: Authenticate and receive JWT token.
   - Purpose: Verifies email and bcrypt password hash. Returns a signed JWT token 
     containing `user_id` and `role`.
   - Permission: Public.
   - Rate Limit: 5 attempts per minute per IP (prevents brute-force attacks).
   - Request Body (`LoginRequest`):
     {
       "email": "admin@givenaija.org",
       "password": "Admin123!"
     }
   - Expected Response (HTTP 200 OK):
     {
       "access_token": "eyJhbGciOiJIUzI1...",
       "token_type": "bearer",
       "user": {
         "id": 1,
         "email": "admin@givenaija.org",
         "role": "admin",
         "is_active": true,
         "created_at": "..."
       }
     }
   - Potential Errors:
     * HTTP 401 Unauthorized: Invalid email or password.
     * HTTP 429 Too Many Requests: Exceeded 5 login attempts within 60 seconds.

--------------------------------------------------------------------------------
TAG 3: CAMPAIGNS (/api/v1/campaigns)
--------------------------------------------------------------------------------

4. GET /api/v1/campaigns
   - Summary: List fundraising campaigns (Cached).
   - Purpose: Returns all fundraising causes. Uses Redis caching with a 60-second 
     TTL. The response object contains `"cached": true` if served from Redis memory!
   - Permission: Public.
   - Query Parameters:
     * `status`: Optional filter ("open" or "closed").
     * `limit`: Items per page (default: 20, max: 100).
     * `offset`: Pagination offset (default: 0).
   - Expected Response (HTTP 200 OK):
     {
       "items": [
         {
           "id": 1,
           "title": "Clean Water for Enugu Rural Communities",
           "description": "Drilling solar-powered boreholes...",
           "goal_amount": 500000000,
           "raised_amount": 5000000,
           "status": "open",
           "created_at": "...",
           "updated_at": "..."
         }
       ],
       "total": 1,
       "limit": 20,
       "offset": 0,
       "cached": false
     }
   - Pro Tip: Execute this endpoint twice in Swagger. The first time `cached` is 
     `false`. The second time `cached` becomes `true` because Redis served it!

5. POST /api/v1/campaigns
   - Summary: Create a new fundraising campaign.
   - Purpose: Allows NGO administrators to launch a new fundraising drive.
   - Permission: ADMIN ONLY (Requires Bearer token with role `admin`).
   - Cache Invalidation: Immediately clears Redis cache `cache:campaigns:*` so 
     visitors see the new campaign right away.
   - Audit Trail: Writes an immutable record to `audit_log` with action 
     `CAMPAIGN_CREATED`.
   - Request Body (`CampaignCreate`):
     {
       "title": "Lagos Orphanage Back-to-School Books",
       "description": "Purchasing 2,000 science and math textbooks.",
       "goal_amount": 200000000
     }
     * Note: `goal_amount` is in kobo (200,000,000 kobo = 2,000,000 NGN).
   - Expected Response (HTTP 201 Created):
     Returns full `CampaignResponse` object with `id`, `status: "open"`, and 
     `raised_amount: 0`.
   - Potential Errors:
     * HTTP 401 Unauthorized: If no token provided.
     * HTTP 403 Forbidden: If caller is a `donor` or `finance` officer.

6. POST /api/v1/campaigns/{id}/close
   - Summary: Close an existing fundraising campaign.
   - Purpose: Marks a campaign as `closed`. Once closed, no further donations or 
     pledges can ever be recorded against it.
   - Permission: ADMIN ONLY.
   - Path Parameter:
     * `id`: Integer campaign ID (e.g. `1`).
   - Expected Response (HTTP 200 OK):
     Returns the campaign object with `status: "closed"`.
   - Potential Errors:
     * HTTP 404 Not Found: If campaign ID does not exist.
     * HTTP 400 Bad Request: If campaign was already closed.

7. GET /api/v1/campaigns/{id}/stream
   - Summary: Live Server-Sent Events (SSE) donation stream.
   - Purpose: Opens a continuous HTTP connection (`text/event-stream`). Whenever 
     a donation is made anywhere in the world to this campaign, the server pushes 
     a live JSON event down the wire instantly without polling the database!
   - Features: Emits a `: heartbeat\n\n` comment every 15 seconds to keep firewalls 
     and reverse proxies from disconnecting.
   - Permission: Public.
   - Path Parameter:
     * `id`: Campaign ID.
   - Note for Swagger: Swagger UI attempts to stream the response. For the best 
     experience, open `http://127.0.0.1:8000/api/v1/campaigns/1/stream` directly 
     in a browser tab!

--------------------------------------------------------------------------------
TAG 4: DONATIONS & PLEDGES (/api/v1)
--------------------------------------------------------------------------------

8. POST /api/v1/donations
   - Summary: Record a confirmed bank transfer as a donation (Idempotent).
   - Purpose: When a donor pays by direct bank deposit or wire transfer, a finance 
     officer logs the bank confirmation reference here.
   - Permission: FINANCE or ADMIN.
   - Hard Problem Armor:
     * Database UNIQUE constraint on `bank_ref`.
     * Idempotency-Key support in HTTP headers.
     * Atomic transaction: Inserts donation + updates campaign raised_amount + 
       adds ledger CREDIT + records audit log.
   - Request Header:
     * `Idempotency-Key`: Optional string/UUID (e.g. `idem-tx-99901`).
   - Request Body (`DonationCreate`):
     {
       "campaign_id": 1,
       "amount": 2500000,
       "bank_ref": "TXN-GTB-20260922-888",
       "member_id": 1
     }
     * Note: `amount` is in kobo (2,500,000 kobo = 25,000 NGN).
   - Expected Response (HTTP 201 Created):
     {
       "id": 2,
       "campaign_id": 1,
       "member_id": 1,
       "amount": 2500000,
       "bank_ref": "TXN-GTB-20260922-888",
       "recorded_by": 2,
       "at": "2026-09-22T12:30:00Z"
     }
   - Testing Idempotency in Swagger:
     1. Supply `Idempotency-Key: test-uuid-001` in the header field.
     2. Click "Execute" -> Returns HTTP 201 Created.
     3. Click "Execute" AGAIN immediately with the SAME key and body!
     4. Result: Returns HTTP 200 OK with the IDENTICAL response payload! 
        No duplicate donation is recorded, and the campaign balance is not touched!
   - Testing Duplicate Bank Reference:
     Change the `Idempotency-Key` but keep the same `bank_ref`.
     Result: Returns HTTP 409 Conflict with code `DUPLICATE_BANK_REFERENCE`.

9. POST /api/v1/pledges
   - Summary: Pledge an amount to a campaign.
   - Purpose: Donors declare their intent to contribute funds in the future.
   - Permission: DONOR, FINANCE, or ADMIN.
   - Request Body (`PledgeCreate`):
     {
       "campaign_id": 1,
       "amount": 5000000
     }
   - Expected Response (HTTP 201 Created):
     {
       "id": 1,
       "member_id": 1,
       "campaign_id": 1,
       "amount": 5000000,
       "status": "pending",
       "created_at": "..."
     }

10. GET /api/v1/donations/me
    - Summary: List donations for current donor.
    - Purpose: Allows a logged-in donor to view their personal giving history.
    - Permission: Authenticated donor.
    - Parameters: `limit` (default: 20), `offset` (default: 0).
    - Expected Response (HTTP 200 OK):
      Returns a paginated `DonationListResponse` containing only donations tied

11. GET /api/v1/receipts/{donation_id}

    - Purpose: Generates or retrieves the single, official, permanent tax receipt

    - Permission: Any authenticated user (Donors can only view their own receipts;

    - Path Parameter:

    - Expected Response (HTTP 200 OK):

17. POST /api/v1/webhooks/payment
    - Summary: Receive payment provider signed webhook.
    - Purpose: The HTTP listener that payment gateways (Paystack, Flutterwave,

    - Permission: Public HTTP endpoint, BUT protected by HMAC-SHA256 signature!

      }

      * HTTP 401 Unauthorized: If `X-Signature` is missing or does not match 
        the HMAC-SHA256 calculation.
      * HTTP 422 Unprocessable Entity: Malformed JSON.

6. CRITICAL REQUEST HEADERS DEMYSTIFIED
================================================================================

When using Swagger UI, you will notice special headers in certain endpoints. 
Here is what they do:

1. `Authorization: Bearer <token>`
   - Handled automatically by Swagger once you click the green "Authorize" button.
   - Encodes the user's identity, role, and expiration timestamp.

2. `Idempotency-Key: <string>`
   - Found on `POST /api/v1/donations`.
   - Protects against network dropouts. If a mobile app or browser retries a 
     donation request due to a transient WiFi glitch, the server checks the 
     `idempotency_keys` table. If the key was already executed, the server 
     returns the cached HTTP 200 response without charging or recording again!

3. `X-Signature: <hex_string>`
   - Found on `POST /api/v1/webhooks/payment`.
   - Computed as: `HMAC_SHA256(secret=WEBHOOK_SECRET, message=raw_json_body)`.
   - Ensures attackers cannot spoof fake payment confirmations.

4. `X-Request-ID: <uuid>`
   - Injected by our custom `RequestLoggingAndTimingMiddleware`.
   - Attached to every incoming HTTP request and mirrored in response headers.
   - If an error occurs, the request ID is included in the error JSON payload, 
     allowing engineers to correlate frontend errors with backend server logs.

7. ERROR HANDLING & THE UNIFORM ERROR SHAPE
================================================================================

A hallmark of senior backend engineering is consistent error structures. 
In GiveNaija, EVERY error response follows an identical JSON contract:

```json
{
  "error": {
    "code": "DUPLICATE_BANK_REFERENCE",
    "message": "Bank reference 'TXN-GTB-20260922-888' has already been recorded.",
    "request_id": "93b48227-d0d1-4cb5-824c-12fa89b25123"
  }
}
```

Key HTTP Status Codes to Know for Your Defense:
- 200 OK: Successful query or idempotent replay.
- 201 Created: New resource created (donation, campaign, user, pledge).
- 400 Bad Request: Business rule violation (e.g. campaign is closed).
- 401 Unauthorized: Missing or invalid credentials / Bearer token.
- 403 Forbidden: Authenticated user lacks required role permissions.
- 404 Not Found: Resource ID does not exist.
- 409 Conflict: Unique constraint violation (duplicate bank reference).
- 422 Unprocessable Entity: Pydantic validation failed (invalid email format, etc.).
- 429 Too Many Requests: Rate limiter triggered (e.g. >5 logins/minute).

10. SWAGGER DEFENSE & VIVA QUESTIONS WITH WINNING ANSWERS
================================================================================

Be ready for these common examiner questions about Swagger and OpenAPI:

Q1: "Where does Swagger UI get its data from? Did you write an HTML file for it?"
A1: "No manual HTML or JSON was written. FastAPI automatically inspects our 
     Python route definitions, type annotations, and Pydantic schemas, compiling 
     them into an OpenAPI 3.1 standard specification at /openapi.json. Swagger UI 
     is a client-side JavaScript application that dynamically parses that JSON 
     specification and renders the interactive browser interface."

Q2: "How does Swagger know which endpoints need authentication?"
A2: "In app/core/deps.py, we defined `security_scheme = HTTPBearer(auto_error=False)`. 
     Whenever an endpoint includes `Depends(get_current_user)` or our role dependencies, 
     FastAPI adds a `security: [{HTTPBearer: []}]` requirement to that endpoint's 
     OpenAPI definition. Swagger UI recognizes this and places the padlock icon 
     next to the endpoint."

Q3: "How does the 'Authorize' button work under the hood?"
A3: "When we paste our JWT access token into Swagger's Authorize modal, Swagger UI 
     stores that token in the browser's local memory. For every subsequent request 
     sent via the 'Execute' button, Swagger automatically adds the standard 
     `Authorization: Bearer <token>` HTTP header to the outgoing request."

Q4: "Can an attacker bypass authentication by calling endpoints outside Swagger?"
A4: "Swagger UI is merely a frontend documentation client. Security is enforced 
     on the backend inside our FastAPI route dependencies (`get_current_user`, 
     `require_admin`, `require_finance`). Whether a request comes from Swagger, 
     cURL, Postman, or an external script, any missing, malformed, or unauthorized 
     token is immediately rejected with HTTP 401 Unauthorized or HTTP 403 Forbidden."

Q5: "Why do your Swagger request bodies already have filled-in sample data?"
A5: "In our Pydantic schema models (e.g. `RegisterRequest`, `DonationCreate`), we 
     used Pydantic's `Field(..., examples=[...])`. FastAPI exports these field examples 
     directly into the OpenAPI schema, allowing Swagger UI to pre-populate request 
     payloads with clean, valid Nigerian NGO data for effortless testing."

Q6: "What is the difference between /docs and /redoc?"
A6: "Both render the exact same underlying OpenAPI specification. `/docs` uses 
     Swagger UI, which is designed for interactive experimentation and testing 
     requests directly in the browser. `/redoc` uses ReDoc, which provides a 
     cleaner, publication-ready three-panel reading layout designed for API 
     consumers and documentation archiving."
